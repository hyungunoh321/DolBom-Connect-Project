# 1. 프로젝트 개요

## 1.1 앱 소개

돌봄 커넥트는 시흥시의 2026년 신규 보육 정책을 기반으로, '초등·영유아 긴급 돌봄 예약'과 '개인 맞춤형 지원금 알림'을 하나로 잇는 통합 모바일 플랫폼입니다.

기존 웹 중심의 정책 정보 전달 방식이 맞벌이 부부의 접근성을 저해하는 문제를 해결하기 위해, 실시간성과 개인화 기술을 결합하여 시흥시민의 정책 체감도를 높입니다.

## 1.2 핵심 가치 및 차별점

- 공신력: 시흥시 공공 데이터 직접 활용
- 실시간성: PostgreSQL Realtime 기반 즉시 동기화
- 개인화: 자녀 수·소득분위 기반 맞춤형 정책 큐레이션
- 편의성: 민간 앱 수준의 실시간 동행 알림 UI

## 1.3 경쟁 앱 분석

| 앱 | 강점 | 한계 | Care-Connect 차별화 |
| --- | --- | --- | --- |
| 아이사랑 (공공) | 전국 단위 방대한 정보 | 시흥시 로컬 혜택 확인 어려움, 딱딱한 UI | 시흥시 특화 데이터 + 직관적 UX |
| 맘시터/자란다 (민간) | 빠른 매칭 | 공적 관리 체계 부재, 지원금 연계 없음 | 공공 데이터 기반 신뢰성 + 지원금 연계 |

## 2.1 사용자 유형별 접근 권한

| 역할 | 접근 가능 화면 | 비고 |

| 일반 보호자 | 로그인, 회원가입, 마이페이지, 맞춤형 혜택, 예약 신청, 예약 현황, 실시간 아이 정보 | JWT 토큰 기반 세션 |

# 3. UX 플로우 (User Flow)

## 3.1 보호자 주요 플로우

- 앱 실행 → 로그인 → 하단 탭 진입
- 맞춤형 혜택: 필터 설정 → 혜택 카드 탭 → 상세 정보 확인
- 예약 신청: 지도에서 기관 선택 → 날짜·시간 선택 → 예약 확인 → 완료 (FCM 알림 수신)
- 실시간 정보: 푸시 알림 수신 → 알림 탭 진입 → 상세 확인

## 3.2 관리자 주요 플로우

- 로그인 (관리자 권한 JWT) → 관리자 전용 탭 진입
- 스케줄 등록 → 예약 현황 조회 → 보호자 알림 전송

# 4. 기술 스택 (Tech Stack)

## 4.1 프론트엔드

| 기술 스택 | 사용 목적 | 비고 |
| --- | --- | --- |
| Kotlin (Android Native) | 안드로이드 네이티브 앱 개발, 비동기 데이터 처리 최적화 | Android 표준 언어 |
| Native Booking Module | 앱 내 독립적 스케줄링 로직 구현 | 자체 개발 모듈 |
| Google Maps SDK | 돌봄 시설 위치 시각화, 사용자 기반 거리 계산 | 지도 API 연동 |

## 4.2 백엔드 및 실시간 통신

| 기술 스택 | 사용 목적 | 비고 |
| --- | --- | --- |
| Supabase (BaaS) | 서버리스 아키텍처 기반 통합 백엔드 | API-less 개발 |
| PostgreSQL Realtime | DB Row 단위 실시간 변화 감지 및 즉시 동기화 | WebSocket 기반 |
| Supabase Auth | 아이디/비밀번호 인증, JWT 기반 권한 분리 및 세션 관리 | 보호자/관리자 역할 분리 |

## 4.3 데이터베이스 및 인프라

| 기술 스택 | 사용 목적 | 비고 |
| --- | --- | --- |
| Cloud PostgreSQL | 예약 기록·보육 정책 데이터 통합 저장, 다중 사용자 실시간 공유 | Supabase 호스팅 |
| 데이터 큐레이션 엔진 | 사용자 조건 기반 맞춤형 혜택 필터링 로직 | 자녀 연령·가구 특성 필터 |
| Serverless Hosting | 24시간 가용성 확보, 인프라 유지보수 부담 없음 | 배포 효율화 |

## 4.4 알림 및 보안

| 기술 스택 | 사용 목적 | 비고 |
| --- | --- | --- |
| FCM (Firebase Cloud Messaging) | 앱 종료·백그라운드 상태에서도 예약 확정·아이 상태 변경 푸시 알림 전달 | Android Push |
| RLS (Row Level Security) | DB 레벨 보안 정책 적용, 비인가 사용자 데이터 접근 원천 차단 | Supabase RLS |
| GitHub | 5주 프로젝트 코드 버전 관리, 팀원 간 개발 진척도 공유 | 형상 관리 |

# 5. 데이터베이스 스키마 설계

## 5.1 users (회원)

| 컬럼명 | 타입 | 설명 | 제약 |
| --- | --- | --- | --- |
| id | UUID | 사용자 고유 식별자 | PK, NOT NULL |
| username | VARCHAR(50) | 로그인 아이디 | UNIQUE, NOT NULL |
| password_hash | TEXT | bcrypt 해시 비밀번호 | NOT NULL |
| role | ENUM | 보호자 / 관리자 / 시스템관리자 | NOT NULL |
| created_at | TIMESTAMP | 계정 생성 일시 | DEFAULT NOW() |

## 5.2 children (아이 정보)

| 컬럼명 | 타입 | 설명 | 제약 |
| --- | --- | --- | --- |
| id | UUID | 아이 고유 식별자 | PK, NOT NULL |
| parent_id | UUID | 연결된 보호자 ID | FK → users.id |
| name | VARCHAR(50) | 아이 이름 | NOT NULL |
| birth_date | DATE | 생년월일 | NOT NULL |
| income_level | INTEGER | 소득분위 (1~10) | NULL 허용 |

## 5.3 reservations (예약)

| 컬럼명 | 타입 | 설명 | 제약 |
| --- | --- | --- | --- |
| id | UUID | 예약 고유 식별자 | PK, NOT NULL |
| parent_id | UUID | 예약한 보호자 ID | FK → users.id |
| facility_id | UUID | 대상 보육 시설 ID | FK → facilities.id |
| child_id | UUID | 예약 대상 아이 ID | FK → children.id |
| reserved_at | TIMESTAMP | 예약 일시 | NOT NULL |
| status | ENUM | 대기 / 확정 / 완료 / 취소 | DEFAULT '대기' |

## 5.4 facilities (보육 시설)

| 컬럼명 | 타입 | 설명 | 제약 |
| --- | --- | --- | --- |
| id | UUID | 시설 고유 식별자 | PK, NOT NULL |
| name | VARCHAR(100) | 시설 이름 | NOT NULL |
| address | TEXT | 시설 주소 (시흥시 내) | NOT NULL |
| latitude | DECIMAL(9,6) | 위도 (Google Maps 연동) | NOT NULL |
| longitude | DECIMAL(9,6) | 경도 (Google Maps 연동) | NOT NULL |
| capacity | INTEGER | 하루 최대 수용 인원 | NOT NULL |
| manager_id | UUID | 담당 관리자 ID | FK → users.id |
| created_at | TIMESTAMP | 등록 일시 | DEFAULT NOW() |

## 5.5 policies (보육 정책)

| 컬럼명 | 타입 | 설명 | 제약 |
| --- | --- | --- | --- |
| id | SERIAL | 정책 고유 식별자 | PK, NOT NULL |
| title | VARCHAR(200) | 정책명 | NOT NULL |
| amount | VARCHAR(100) | 지원금 표현 문자열 (예: '월 20만원') | NOT NULL |
| category | VARCHAR(50) | 정책 분류 (예: 양육, 교육, 의료) | NOT NULL |
| tags | TEXT[] | 필터용 태그 배열 (예: {24개월 미만}) | NOT NULL |
| description | TEXT | 정책 상세 설명 | NOT NULL |
| target | TEXT | 지원 대상 설명 | NOT NULL |
| period | VARCHAR(200) | 지원 기간 설명 | NOT NULL |
| how_to_apply | TEXT | 신청 방법 안내 | NOT NULL |
| documents | TEXT[] | 필요 서류 배열 (예: {주민등록등본}) | NOT NULL |
| is_recommended | BOOLEAN | 맞춤 추천 여부 | DEFAULT FALSE |

# 6. 비기능 요구사항

## 6.1 성능

- 앱 콜드 스타트: 3초 이내
- 실시간 알림 지연: 2초 이내 (PostgreSQL Realtime)
- 지도 렌더링: 2초 이내 (Google Maps SDK)

## 6.2 보안

- 모든 API 통신 HTTPS 적용
- JWT 만료 시간 설정 (Access Token 1시간, Refresh Token 7일)
- RLS 정책 — 사용자는 자신의 데이터만 R/W 가능
- 비밀번호 bcrypt 해시 저장 (salt rounds ≥ 10)

## 6.3 가용성

- Supabase Serverless 기반 99.9% SLA
- FCM 백그라운드 알림 — 앱 종료 상태에서도 수신 보장

# 7. 팀 구성 및 역할

| 팀원 | 기여도 | 담당 역할 | 주요 산출물 |
| --- | --- | --- | --- |
| 오현근 (팀장) | 30% | 백엔드·DB 총괄, 프로젝트 일정 관리 | PostgreSQL 스키마, Supabase RLS, 시스템 관리자 페이지 BE |
| 안현빈 | 25% | 프론트엔드 (인증·혜택) | 로그인·마이페이지 화면, Supabase Auth 연동, 정책 필터링 알고리즘 |
| 김준서 | 25% | 프론트엔드 (지도·예약) | Google Maps SDK, 예약·관리자 페이지, Native Booking Module |
| 김병수 | 20% | 백엔드·실시간 통신 | FCM 푸시 알림, PostgreSQL Realtime, 실시간 아이 정보 BE |

# 8. 구현 난이도 평가

전체 구현 난이도: 중-상 (Mid-High)

## 8.1 난이도 상향 요인

- Supabase 기반 실시간 데이터 동기화 구현
- 사용자 특성 기반 맞춤형 정책 큐레이션 알고리즘
- 보호자-보육원관리자-시스템관리자 3단계 권한 분리
- FCM 알림 시스템과 PostgreSQL Realtime의 유기적 결합

## 8.2 리스크 완화 전략

- API-less Development으로 개발 공수 절감, 핵심 로직 완성도에 집중
- BaaS 활용으로 인프라 관리 부담 최소화
- GitHub 형상 관리를 통한 5주 일정 가시성 확보
